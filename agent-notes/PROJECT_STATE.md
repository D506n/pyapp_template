# Состояние pyapp_template

## Согласованный объём

Copier-шаблон асинхронного Python 3.14 сервиса: FastAPI, FastMCP (HTTP/stdio;
совместно с FastAPI — одно ASGI-приложение), SQLAlchemy asyncio с PostgreSQL/asyncpg,
SQLite/aiosqlite и MySQL/asyncmy, Alembic, опциональные pydantic-settings/httpx.
Стандартный logging. FastAPI сохраняет входной X-Trace-ID в ContextVar; без
заголовка — None, без генерации ID и добавления заголовка ответа.

В корне — Copier и руководство; в template/ — создаваемый проект и переносимые
AGENTS.md, AGENTS.project.md, CODESTYLE.md. Генерация только создаёт файлы;
bootstrap и миграции выполняются явно. CI, Redis и контейнеризация не включены.
Лицензия шаблона MIT; лицензия проекта выбирается отдельно, исходное MIT notice
сохраняется также при выборе none.

## Готовность на 2026-11-20

1. Контракт и переносимые правила — готовы.
2. Реализация Copier и приложения — готова.
3. Локальные рецепты и тестовая среда — проверены.
4. Независимые тесты и итоговое ревью — пройдены.
5. Коммит и публикация — ожидают разрешения человека на конкретный состав.

Проверено: 7 контрактных методов генератора, матрица 10 конфигураций,
135 runtime-тестов без skip/xfail; реальные HTTP и MCP HTTP/stdio/combined;
SELECT 1 и цикл Alembic для всех трёх БД; сборки wheel/sdist MIT и none;
интерактивный опрос и явный bootstrap трёх вариантов.

Полный just precommit-check-agent пройден для генератора, HTTP, MCP stdio и
совместного SQL-варианта. Ревизии миграций форматируются по описанному в README
сценарию перед проверками и применением. Bandit без находок/ошибок; pip-audit
не нашёл известных уязвимостей зависимостей. Сам локальный тестовый пакет,
отсутствующий в PyPI, pip-audit проверить не может: безопасность его кода этим
аудитом не подтверждается. Технический аудит сетевых syscalls генерации не делался.

Исправлены и перепроверены Unicode TOML, сохранность notices в сборках,
регистр trace-заголовка, коллизии имён и завершающий перевод строки. Итоговое
ревью и адресная перепроверка замечаний пройдены; проверка исполнением и
чтение кода в отчётах различаются.

Цель публикации — публичный D506n/pyapp_template. На момент подготовки репозиторий
ещё приватный; кандидат находится в рабочей ветке feat/copier-async-service-template.
Коммитов/push/merge не выполнено. Следующий шаг — одобрение человеком состава
коммита, затем публикация рабочей ветки и запрос на слияние; слияние делает человек.
